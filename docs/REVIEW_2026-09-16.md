## Confirmed defects repaired

* Arbitrary old sigmoid/floors could keep broken armor protective. Replaced with a
  sourced, versioned community curve and explicit broken-armor bypass.
* Armor-damage percent was ignored, corrupting wear and subsequent-shot curves.
* Unreached backing layers lost durability in analytic calculations.
* Shotgun expectation multiplied a first-pellet result instead of consuming armor
  between all-hit pellets. Sequential simulation replaces that shortcut.
* First-shot and entire-burst damage were conflated across modes.
* First-penetration event probabilities incorrectly assumed independence after wear.
* Disabled armor mismatched timeline columns; zero-shot durability was absent.
* Stomach HP loss was treated as immediate death; that unsupported estimate is removed.
* Editing a layer appended another layer. Update/add are now separate operations.
* Missing original/repaired durability controls made repaired armor ambiguous.
* Fast asynchronous input changes could display stale calculation results. Both
  frontends invalidate stale results and use generation/cancellation safeguards.
* Fixed-size dialogs and input panels overflowed narrow windows. Desktop is tested
  at 360, 390, 800 and 1440 pixels; Android uses width-aware scrollable layouts.
* Same short names/material thumbnails were not safe image identities. All 222
  shipped records use exact IDs and checksummed images; missing IDs show placeholders.
* Old/historical API fallback data could replace current bundled facts, and partial
  sync erased missing rounds. Validated merge and cache retention replace that behavior.
* Builds only ran on tags/manual actions, and Android signing assumptions could fail
  publication. The release pipeline builds both platforms, tests actual binaries,
  preserves evidence and publishes verified artifacts with explicit signing labels.

## Scope and remaining uncertainty

Read `RESEARCH.md` before interpreting numbers. Exact current-server algorithms are
not established by software tests. Post-penetration/wear/blunt functions remain
community assumptions; backing-soft blunt attenuation and full flight physics are
not implemented. Live tarkov.dev refresh was unavailable during this audit. Data is
identified as a Wiki-reviewed snapshot, not falsely called a complete live refresh.
Armor templates cover 38 plates; arbitrary soft-armor and helmet layers are editable,
but this is not a complete per-hitbox carrier/helmet compatibility database.

The code was inspected and tested directly. CodeRabbit CLI and the connected Codex
workspace were unavailable in this environment; no automated CodeRabbit review is claimed.
